# AccountaBall v3.1 — Manual QA Checklist

_Status: not yet run. Automated coverage is green (223 unit tests + 10 live
integration tests, build clean). The items below are the runtime/UI behaviors
that automation can't exercise._

## What's now automated (run these instead of testing the AI by hand)
The real AI-provider logic is covered by an opt-in live suite — `make -C src test-integration`
(requires Ollama running). It verifies, against the actual model:
- `healthCheck` true (model present) / false (daemon unreachable) / false (model not pulled)
- on-task vs off-task **classification** on clear screens
- **excuse evaluation** — aligned → justified, unrelated → not justified (clears v3 findings #2/#3)
- **session summary** returns parseable per-task commentary
- a real classification driven through the engine's `processCycle`

So the checklist below is now only the **GUI / animation / permission / timing**
behaviors that need human eyes.

## Prerequisites
- macOS 14+ with **Screen Recording** permission granted to the app
- **Ollama** running with the model pulled: `ollama run qwen2.5:7b`
- Run: `make -C src run`
- Then repeat the AI-dependent checks with the cloud provider:
  `AI_PROVIDER=openrouter OPENROUTER_API_KEY=… make -C src run`

## Checklist

### Provider availability (Phase A)
- [ ] **Launch with Ollama stopped** → the "AI unavailable" card appears immediately at launch (not only after a session starts).
- [ ] While down, you are **never** falsely prompted with "what are you doing?" (errors must not score as off-task).
- [ ] **Start Ollama** (and ensure the model is pulled) → the card auto-dismisses and the session resumes within ~5s.
- [ ] **CRITICAL — capture actually restarts after recovery.** After auto-resume, confirm screen-watching is genuinely live again (e.g. switch to an off-task app past the settle window and verify it still notices). This guards the `isCapturing` edge fix in `9996f93` — the ball returning to "on-task" is necessary but **not** sufficient; the loop must really be running.

### Grace window + prompt suppression (Phase B)
- [ ] **Fresh session:** no off-task prompt during the first ~15s even if you're clearly off-task.
- [ ] Open the **session log / progress** screen → no "what are you doing?" interruption while it's open; the timeline still records in the background.

### Excuse evaluation (verdict logic now automated — verify the UI only)
_The accept/reject logic is covered by `make test-integration`. Here, just check the panel UX:_
- [ ] Go off-task → the excuse input appears; typing + submit shows "Checking…" then the verdict message, and an accepted excuse returns you to the session.

### Session-completion breakdown (Phase C)
- [ ] Finish a session → completion screen shows the **timeline ranges** (contiguous activity blocks, off-task stretches labeled).
- [ ] Completion shows **per-task comments**; a **repeated** task shows faster/slower vs last time + average.
- [ ] Kill the AI mid-finalize (or run with it down) → completion still renders the timeline + local comparison numbers (never a blank screen).
- [ ] Reach completion via **both** paths: the AI `DONE:n` classification *and* the manual checkoff in the progress panel — recap populates in both.

### Cross-provider
- [ ] Repeat the AI-dependent checks above with `AI_PROVIDER=openrouter`.
- [ ] Note any residual classification-accuracy / prompt-tuning issues (v3 findings #2/#3) for follow-up.
