# AccountaBall v3.2 (Phase 1) — Manual QA Checklist

_Status: not yet run. Automated coverage is green (~299 unit tests + a live Ollama
3-state-bias integration test, build clean). The items below are the runtime / UI /
timing / model-feel behaviors that automation can't exercise._

_See [docs/HOW-IT-WORKS.md](docs/HOW-IT-WORKS.md) for how the whole flow operates._

## What's already automated (don't hand-test these)
- 3-state **parse** (TASK / AMBIGUOUS / OFFTASK / DONE), prompt parity across providers.
- The **drift engine**: derived `driftCount` counts only confirmed off-task events;
  `commitmentBroken` at the limit; ambiguous/auto-return never inflate drift;
  returning-to-work mid-prompt does not inflate drift; ask-once dedupe.
- The **timed break** suppresses prompting/suspicion/drift and resumes after the window.
- **Auto-return** logging for ignored prompts; the **transparency log** time-ordering
  and drift-summary surfacing; `JustificationEvent.kind` persistence.
- A **live** `make -C src test-integration` case confirms the real model honors the
  bias-toward-ON/AMBIGUOUS on a borderline screen (never a false OFFTASK).

So the checklist below is the **GUI / animation / permission / timing / how-it-feels**
behavior that needs human eyes.

## Prerequisites
- macOS 14+ with **Screen Recording** permission granted.
- **Ollama** running with the model pulled: `ollama run qwen2.5:7b`.
- Run: `make -C src run`.
- Suggested setup for a fast pass: declare **2 tasks**, set the **drift limit to 2**.
- Repeat the AI-dependent checks with the cloud provider:
  `AI_PROVIDER=openrouter OPENROUTER_API_KEY=… make -C src run`.

## Checklist

### Setup — the pre-commitment
- [ ] The setup screen shows the **drift-limit stepper** (default 3) below the task
      rows; the "Start session" button stays pinned/reachable; the panel never exceeds
      the display.
- [ ] Set the limit, start, finish, then start again → the stepper **remembers** your
      last value (re-shown for re-confirmation, not reset to 3).
- [ ] The stepper clamps to **1–10** (can't go below 1 or above 10).

### ON_TASK — silence done well
- [ ] Work clearly on a declared task → the ball stays **silent** on the edge; no
      prompts, no faces changing to off-task. (The most important behavior is *nothing*.)
- [ ] The per-task timer on the ball **accrues** while you're on task.

### Settle window
- [ ] **Fresh session / just resumed:** no prompt during the first ~**15s** even if
      you're clearly off-task.

### AMBIGUOUS — the calm one-time ask
- [ ] Open something genuinely **borderline** (a generic spreadsheet/doc that *could*
      be the task) → the calm card appears **once**:
      *"Quick check — is this part of {task}?"* with an optional reason field and
      **[ Yes, it's related ] [ No, I drifted ]**. No exclamation marks, no scolding.
- [ ] Tone check: it reads like a mirror, not a boss.
- [ ] **Yes, it's related** (with or without a typed reason) → returns you to the
      session; the **same activity is not asked again** this session (stay on it / come
      back to it → silence).
- [ ] **No, I drifted** → goes straight to the OFF break/resume card (below), and that
      counts as a drift.
- [ ] **Ignore the ambiguous card for ~2 min** → it auto-dismisses and resumes
      (logged as an auto-return, see recap).
- [ ] It only ever asks about your **first** task (known Phase-1 limitation — confirm
      it's not surprising in use).

### OFF_TASK — the calm break/resume choice
- [ ] Open something **clearly** off-task (a game, social feed) → after **2 consecutive**
      reads (outside the settle window) the card appears:
      *"You've drifted from {task}."* with **[ Take a timed 5-min break ] [ Jump back in ]**.
      No "get back to work," no scold face as the main signal.
- [ ] A **single** stray off-read does **not** trigger the card (needs 2 in a row).
- [ ] **Jump back in** → silent return to the session.
- [ ] **Return to a real task while the card is up** → it auto-dismisses; this
      self-return is **not** counted against you (verify in the recap).
- [ ] **Ignore the card for ~2 min** → auto-return; monitoring resumes.

### Timed break
- [ ] **Take a 5-min break** → the ball goes quiet and shows a **countdown** ("break
      4:59 → …"); the face relaxes.
- [ ] During the break: open something off-task → **no prompt**, **no drift counted**.
- [ ] Finish a task during the break → completion still fires.
- [ ] When the countdown ends → monitoring **silently resumes** (off-task again now
      prompts normally).

### The drift budget (the mechanism)
- [ ] With the limit at 2: drift **once** → recap will later show "Drift 1 of 2".
- [ ] Drift to/over the limit → the ball keeps offering the **calm** choice
      mid-session (there is **no** in-the-moment punishment or escalation).
- [ ] You **cannot** change the drift limit mid-session (it's setup-only).

### Session recap — the transparency log (the payoff)
- [ ] Finish the session (all tasks done, via AI `DONE` **and** the manual checkoff in
      the progress panel — try both) → the completion screen shows a **"Your checks"**
      panel listing every check in time order, calm past tense:
      `◐` ambiguous you clarified (with your reason), `●` a confirmed drift,
      `○` an auto-return.
- [ ] An **empty** ambiguous reason renders gracefully ("you marked it related", **not**
      `you marked related: ""`).
- [ ] The **"Drift N of LIMIT"** line shows; it's calm (white) when **under** the limit.
- [ ] When the limit was **hit**, a single firm **red** line appears:
      *"✕ Commitment broken — you set a limit of L, you hit N."* — the one place the app
      is not soft. Under the limit → no red, no "failed."
- [ ] Per-task commentary still renders; kill the AI mid-finalize (or run with it down)
      → the checks + drift summary + local comparisons still render (never a blank recap).

### Provider availability (regression from v3.1 — still holds)
- [ ] **Launch with Ollama stopped** → the "AI unavailable" card appears at launch.
- [ ] While down, you are **never** falsely prompted (errors must not score as off-task).
- [ ] **Start Ollama** → card auto-dismisses, session resumes within ~5s, and
      **capture genuinely restarts** (switch off-task past the settle window and confirm
      it still notices — the ball returning to on-task is necessary but not sufficient).

### Cross-provider
- [ ] Repeat the AMBIGUOUS / OFF / recap checks with `AI_PROVIDER=openrouter`.
- [ ] Note any classification-accuracy / bias differences (does the cloud model also
      prefer ON/AMBIGUOUS over a false OFFTASK on borderline screens?).

### How it feels (qualitative — capture for Phase 2)
- [ ] Does the AMBIGUOUS ask fire **too often** / not enough? (cadence)
- [ ] Is the **5-min** break the right length?
- [ ] Does the recap **land** — does the transparency log + "Drift N of LIMIT" feel
      honest and motivating, or flat / preachy?
- [ ] Anything that feels like a **boss** rather than a **mirror** (tone leaks)?
