# 3-State Accountability — Phase 1 (the spine) Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Replace the binary on/off nag with a calm 3-state "mirror" you can run and feel: classify ON / AMBIGUOUS / OFF, a one-time calm ask on AMBIGUOUS, a no-scold break/resume choice on OFF, a deterministic Swift drift engine against a pre-committed limit, and an honest transparency log in the session recap.

**Architecture:** Architecture B — the model only *perceives* (`{state, label}`); Swift owns every decision. `DRIFT_COUNT` is **derived** (count of confirmed off-task `JustificationEvent`s this session), never a mutable tally, so it can't desync and is trivially testable. The drift limit is set once at setup and is immovable in-session. No streak, no commitment line, no adaptive cadence, no confidence threading — those are Phase 2 (deliberately deferred; see "Out of scope").

**Tech Stack:** Swift + SwiftUI, SwiftData (lightweight migration via a defaulted new field), the existing `MicroTest` harness (`expect`/`suite`), Ollama/OpenRouter classify prompts.

**Design reference:** `planning/plans/2026-06-07-3state-accountability-design.md` (Sections 1–4, APPROVED).

**Out of scope (Phase 2/3 — do NOT build):** cross-session streak, optional commitment line, adaptive cadence, the model's `confidence` value, suspicious-claim clustering. If a task tempts you toward these, stop and leave a `// Phase 2:` note instead.

**Conventions:**

- New test suites must be registered in `src/Tests/TestRunner/main.swift` (see how existing suites are wired).

```swift
enum MultiTaskResult: Equatable {
    case onTask(index: Int, label: String)
    case ambiguous(label: String)   // model genuinely can't tell
    case offTask(label: String)
    case done(index: Int, label: String)

    static func parse(_ raw: String) -> MultiTaskResult {
        let parts = raw.split(separator: "|", maxSplits: 1, omittingEmptySubsequences: false)
        let keyword = parts.first.map { String($0).trimmingCharacters(in: .whitespacesAndNewlines).uppercased() } ?? ""
        let label = parts.count > 1 ? String(parts[1]).trimmingCharacters(in: .whitespacesAndNewlines) : ""
        if keyword == "AMBIGUOUS" { return .ambiguous(label: label) }
        if keyword == "OFFTASK" { return .offTask(label: label) }
        if keyword.hasPrefix("TASK:"), let idx = Int(keyword.dropFirst(5)) { return .onTask(index: idx, label: label) }
        if keyword.hasPrefix("DONE:"), let idx = Int(keyword.dropFirst(5)) { return .done(index: idx, label: label) }
        return .offTask(label: label)
    }
}
```

> Note: the default fallback stays `.offTask` (an unparseable line is treated as drift, not silently swallowed). The design's "bias toward ON/AMBIGUOUS when unsure" is enforced in the *prompt* (Task 2), not the parser.
